## 2. 採集の方式（第1〜6章と同じ）

1. **通読で引っかかった文をすべて拾う。理論による選別をしない。** ×だろうと思っても網に載せる。容認判断は当てにならないことが実測で確定している（×予測の的中は第5章 0/5・第6章 1/5。リズム原則 v8 §4「容認の判断を判定の根拠にしない」）。
2. 各標本の構成: 本文からの**逐語引用**（位置指定は行番号でなく本文文字列）／引っかかりの説明（リズム原則の根・過去標本との同型を示せる場合は出典つきで示す。示せない違和感もそのまま出す——条文にない違和感を捨てないこと）／確信度（高・中・低・×予測）／案（高確信は必ず、中以下もできる限り）。
3. **機械走査**: `uv run python tools/style_check.py --files chapters/statistical_test_precise.tex` を実行し、出力の全件を確認する。基準値（2026-08-16 時点）: block 26件（大半は章番号参照で全書トラック対象）・flag 21件（ぶつん切れ疑い12・列挙6・問い2・名詞化1）。**走査に出たものは全件、標本の場に出す**。自分の判断で容認して落とさない（第6章で「向き」4箇所を容認で落とした失敗が v8 §4 に記録されている）。
4. 標本の途中で規則が確定的に見えたら、**その場で章全体に走査を掛け直す**（v8 §4）。
5. 成果物: `docs/言い回し標本_第7章.md`。第6章の文書と同じ構成（冒頭に方式、標本、走査で出たもの、判定欄、全書トラック登録、申し送り）。

## 3. 第6章パスからの申し送り（必ず標本に立てる）

いずれも本文文字列で示す。行番号は目安にすぎない。

1. **「向き」参照の食い違い**: 「第6章で決めたとおり, 向きを指定しない両側検定である.」——第6章は「向き」を全廃済み（確定した言い方は「どちらが大きいかまで決めて問う場合を片側検定, 差があるかどうかだけを問う場合を両側検定と呼ぶ」）。この文は存在しない決定を参照している。
2. **「向き」「方向」の残り**: 「差がどちらの向きであれ」「対立仮説は, 特定の方向を仮定していない.」「ずれの向きがどちらであれ」——第6章の確定（読者にとっての中身で書く: どちらが大きいか／期待度数より多いか少ないか）と突き合わせる。「行と列の両方向で」は表の行・列の話で型が違う可能性があるが、判定の場に出す。
3. **変な立場（受け取りの構図）2箇所**: 「第6章で先に受け取った『原作の有無で平均視聴回数に差がある』という結論は, この計算から出ていたのである.」／「第6章で受け取った結論の数値は, すべてこの道筋から出てきたものである.」——読者を「結論を受け取る人」に立てている疑い。禁則は確定済み（リズム原則 v8 §3「変な立場を持ち込まない」）だが、差し替えは**都度判定**なので案を作って判定欄に出す。
4. **「問い」の抽象用法**: 「差があるかという問いを, t検定の手順に載せるところまで進めた.」（「ところまで進めた」の抽象締めも同居）／「『血液型と性格タイプに関係があるのか』という問いを取り上げた.」（こちらは具体的な疑問文を指しており可の可能性が高い。両方とも判定の場に出す）。
5. 第7章冒頭の**進路宣言とスキップ案内の整合**は維持する（章の設計そのものは対象外。第6章末の案内と食い違う案を作らない）。

## 4. 起草の手順（v8 §4 の縛りをそのまま適用）

- 網に掛かった語だけを見ない。**その文の残りと段落の構造まで読んでから**標本に立てる（第6章で三度失敗した型）。
- 言い直しに見える二文は、語ではなく**情報**で比べる。
- 案を差し替えるたびに、**その文と前後のつながりまで全文を通して読み直す**。
- 冗長・ヘッジ・重複を外す前に、それが何を防いでいるかを言葉にする。
- 起草した案は提出前に自己点検する: 抽象語一語の締め／ぶつん切れ／述語を省いた引用句・体言・数値止め／自問の語尾（か.→だろうか）／遠称指示語／名詞化／「問い」「と読める」／作った場面や立場。
- 数理に触れる案（この章は計算の説明が本体）では、**理由づけを数学的に確かめてから書く**。成り立たない理由を作らない（v8 ペア11 の棄却中間版2つが実例）。説明の深さは「これ以上言うと説明しすぎ, これ以下だと曖昧」の線を探す。

## 5. Codexレビュー（試験導入）

**位置**: 標本文書の草稿（標本＋案）が揃った後、Ryosuke に出す**前**。

**方法**: Codex プラグイン（codex:rescue）でレビュータスクとして投げる。編集タスクではないので本文の編集は依頼しない。運用の既知の注意: ジョブが起動直後に無言死することがある（ログ1行のまま）。ログが Thread ready に到達したのを確認してから待つ。死んだら --fresh で投げ直す。

**Codex への指示テンプレート**（修正案の一覧と、リズム原則 v8 の本文を添えて、このまま使う）:

> あなたは統計学教科書（文系大学生・社会人向け）の文体修正案のレビュー担当です。以下の修正案（旧文→新文）を、教科書の読者として読んでください。
>
> してほしいこと: 新文に残っている欠陥、または新文が新たに持ち込んだ欠陥を指摘する。
>
> 各指摘には根拠を必ず一つ添える: (a) 本文・修正案の該当文字列とその問題の説明、(b) 辞書的事実（語の意味・用法の誤り）、(c) 添付のリズム原則の該当項目。
>
> してはいけないこと: 代わりの文章を書くこと（書き直し案の提示は禁止。欠陥の指摘まで）。リズム原則を上から順に照合するチェックリスト式のレビュー（項目の充足ではなく、読んで引っかかるかで判断する。原則は根拠の参照用）。根拠のない語感だけの指摘。
>
> 出力: 指摘ごとに「対象（標本番号と該当文字列）／欠陥／根拠」。指摘がなければ「なし」と書く。

**採否**: Codex の各指摘について、このセッション（判定役代行）が採否を決める。採った指摘だけ起草に反映する。反証を素通しで Ryosuke に出さない。

**記録（試験の較正データ。標本文書末尾に必ず残す）**:

| # | 対象標本 | Codexの指摘（要約） | 根拠の種別 (a/b/c) | 採否と理由 | Ryosuke判定後の的中 (後記入) |
|---|---|---|---|---|---|

集計欄: 指摘総数／採用数／棄却数。Ryosuke 判定後に「採用した指摘が○になった数」「棄却した指摘が実は当たっていた数」を追記できる形にする。この数字で機構を続けるかを判断する。
